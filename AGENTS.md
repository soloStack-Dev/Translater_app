# Aura AI — Voice Assistant (Next.js 16 App Router)

## Commands
- `npm run dev` — dev server (Turbopack; Next 16 default).
- `npm run lint` — ESLint flat config. Do NOT use `next lint` (removed in v16).
- `npm run build` — production build. `next build --webpack` opts out of Turbopack.
- No test framework configured.

## Project layout
- `app/` — App Router pages: `page.tsx` (home), `features/page.tsx`, `voice/page.tsx`, `api/tts/route.ts` (Sarvam proxy), `api/chat/route.ts` (speech → STT → LLM). Layout uses `LayoutProps<"/">` typing (generated by `next dev`).
- `components/` — shared `Navbar.tsx`/`Footer.tsx` + per-page sections. `components/voice/` holds the voice page pieces: `HeroVisual` (decorative animation), `LanguageSelector`, `TypeToSpeakPanel`, `SpeakToAuraPanel`. `components/smoothui/dynamic-island/` is scaffolded but unused by pages.
- `hooks/` — `useSpeechRecorder.ts`: MediaRecorder wrapper (start/stop, 30s auto-stop); caller owns all UI state. IMPORTANT: stop mic tracks inside `onstop` (after the encoder flushes) — calling `track.stop()` right after `recorder.stop()` yields an EMPTY blob in Chrome → 400 "Audio is required" from /api/chat.
- `asserts/Home-asserts/`, `asserts/Feature-asserts/` — local images for home/features pages, imported as `@/asserts/...`. They are NOT in `public/`, so only `public/` assets are served at `/...`.
- `Context/` — authoritative design/build specs (`Homepage/`, `Featurepage/`, `Voicepage/`, `sarvam-model-setup.md`). Follow them for copy, colors, and layout; the specs' TTS snippet is stale (see Sarvam notes below).
- `UIDesign/` — reference screenshots (optional).
- `lib/` — `utils.ts` (`cn`), `languages.ts` (client-safe single source of language metadata), `reveal.ts` (gsap entrance/scroll/stagger helpers used by all pages), `sarvam.ts` (server-only Sarvam helpers: `generateAuraReply`, `transcribeAudio`, `synthesizeSpeech` — shared by both API routes).
- `app/globals.css` — Tailwind v4 `@theme`, design tokens, keyframes. Use Tailwind utilities + plain CSS here for alignment/positioning.

## Stack & conventions
- Next 16.3 + React 19.2 (Turbopack). Read `node_modules/next/dist/docs/01-app/` before framework code: `params`/`searchParams` are async; `next lint` removed; smooth scroll needs `data-scroll-behavior="smooth"` on `<html>`.
- Pages with gsap/ScrollTrigger are client components (`"use client"`); gsap must run in `useEffect` inside `gsap.context()` (see `lib/reveal.ts`) and be cleaned up.

## Sarvam TTS (voice page)
- API key is in `.env` as `SARVAM_API` (gitignored) — never hardcode it. Read in `lib/sarvam.ts` (`createSarvamClient`).
- Voice page structure: `app/voice/page.tsx` is a slim page (language + input-mode state, segmented toggle, layout) that composes `components/voice/*`. Only ONE input block renders at a time: `inputMode: "type" | "speak"` (default "type") decides which panel is rendered (`{inputMode === "type" ? <TypeToSpeakPanel/> : <SpeakToAuraPanel/>}`). The inactive panel is NOT mounted — this is what "show only one input block" means here. Each panel resets itself on language change with the in-render `prevLanguageCode` pattern (state reset during render, ref update in a `useEffect`) to satisfy the `react-hooks/set-state-in-effect` and `react-hooks/refs` lint rules. The earlier `key={languageCode}` remount approach was removed: it made panels pop in without their gsap fade and caused double-highlight glitches.
- Text flow (`app/api/tts/route.ts`): user types in ANY language or romanized/mixed form (English, Hindi, Tamil, Malayalam, Kannada, Hinglish, Tanglish — e.g. "hey enna pandra eppo?") → `generateAuraReply(lang, text)` (LLM) → `synthesizeSpeech(lang, reply)` (TTS) → returns ONLY `{ audioBase64 }` (voice-only; reply text is NOT returned to the client).
- Speech flow (`app/api/chat/route.ts`): `useSpeechRecorder` records on the client (MediaRecorder, webm/opus) → base64 POST → `transcribeAudio(buffer, mimeType)` (saaras:v3, auto-detects spoken language, handles romanized/mixed speech) → `generateAuraReply(lang, transcript)` → returns `{ transcript, response }` as UTF-8 JSON.
- `auraSystemPrompt` (in `lib/sarvam.ts`) enforces native script: reply MUST be in the selected language's script (Devanagari/Tamil/Malayalam/Kannada), even if the user wrote romanized text. Without this STRICT rule, `sarvam-105b` mirrors the user's romanization (e.g. replies "Vanakkam! Naan nallaa irukken..." instead of Tamil script), which makes bulbul TTS mispronounce.
- Verified against installed SDK (`sarvamai@1.1.8`) types — these differ from `Context/sarvam-model-setup.md`:
  - TTS request field is `language_code`, NOT `target_language_code`.
  - `bulbul:v3` rejects `pitch`/`loudness`; use `pace` (0.5–2.0) and `temperature`.
  - Speaker must be a lowercase v3 voice, e.g. `speaker: "ritu"`.
  - Old translation-only path is gone: `client.text.translate` same-language normalization is rejected ("Source and target languages must be different"), so script normalization is handled by the prompt, not the translate API.
  - Chat `sarvam-105b` is a reasoning model: it spends many tokens in `reasoning_content`. Do NOT cap `max_tokens` low or `content` comes back empty — set `reasoning_effort: "low"` and omit `max_tokens` (verified: empty content bug caused by `max_tokens: 300`).
  - `speechToText.transcribe` takes `file: { data: Buffer, contentType, filename }` (Uploadable), response has `transcript` and `language_code`.
- `sarvamai` is server-only; keep it in `serverExternalPackages` in `next.config.ts` and never import it into client components.
